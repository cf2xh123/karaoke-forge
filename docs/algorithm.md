# 对齐算法

Karaoke Forge 使用“识别定位 + 正式歌词回填”，而不是把语音识别结果直接导出。

1. `faster-whisper` 从歌曲或分离后的人声中生成带开始/结束时间的识别词。
2. 正式歌词和识别词使用相同规则规范化：
   - Unicode NFKC 归一化；
   - 英文等空格语言按单词切分；
   - 中日韩文字按字符切分；
   - 标点保留在显示文本中，但不参与匹配。
3. 全局动态规划按顺序匹配两组词元。完全相同的词权重最高，模糊相似词次之，插入和缺失词使用间隙惩罚。
4. 已匹配词采用可靠 ASR 锚点的开始与结束时间，保留真实停顿；未匹配词优先在前词结束到后词
   开始之间的空隙插值，不截短前词的拖音。空间不足时使用最短估算并标记待复核。
5. 最后按原始歌词行重新组合，生成行级和词级时间轴。

这个方案的主要优点是拼写、标点、大小写和歌词版本由用户控制。其限制也很明确：

- Whisper 的词级时间戳并非音素级强制对齐；
- 歌声、和声、混响和密集伴奏会降低识别质量；
- 大段漏唱或歌词版本不一致会让插值区间变长；
- 中日韩语言目前是字符级高亮，并不自动按语义词或音节合并。

JSON 是信息最完整的中间格式。0.12.0 的逐行精确对齐和以后可选的音素级后端都复用
同一数据模型，不需要改变其他导出器和视频渲染代码。

## 三档识别配置

网页和命令行把常用配置归纳为三个预设：

| 档位 | 模型与搜索 | 后处理 |
| --- | --- | --- |
| 快速 | `small`，beam 3 | 使用下文的可靠锚点粗对齐 |
| 均衡（默认） | `large-v3-turbo`，beam 5 | 使用可靠锚点粗对齐 |
| KTV 精准 | `large-v3`，beam 5 | 粗对齐后再运行逐行 CTranslate2 强制对齐 |

第一次选用某个模型时需要下载模型文件。`large-v3-turbo` 和 `large-v3` 明显大于
`small`，首次下载、校验和加载可能需要较长时间，之后会从本机缓存读取。

KTV 精准会优先尝试用 Demucs 提取人声，以减少伴奏、和声和混响对定位的干扰。这个自动
尝试是可降级的：Demucs 未安装或运行失败时记录原因并继续使用原音频。用户手动勾选“先
分离人声”表达的是严格要求，此时分离失败会停止并报告错误，不会隐式改用原音频。

## 已有行级时间轴的句内精修

普通 LRC、SRT 和 VTT 往往只标注整句的开始与结束。直接把时间平均分给每个字，会在
拖长音、抢拍和句中变速时造成扫色赶不上或超前。默认精修流程会：

1. 用 Whisper 识别整段音频并做一次全局歌词匹配；
2. 只有形成足够可靠的行首锚点链，才校正合成时间轴的整段偏移或渐进漂移；
3. 在校正后的句区间内寻找实际演唱的逐字时间。相同文本出现多次时，对接近当前句首的候选
   给予轻量偏好，同时保留找回大幅整体偏移的能力；
4. 只采纳通过覆盖率、置信度和边界检查的结果；其他行保留原先时间，等待试听复核。

网易云 YRC 已含真实逐字开始时间和持续时间，解析后会标记为来源时间。网页和命令行
共用 `off`、`auto`、`force` 三档策略：`off` 完整保留输入时间；`auto` 只精修标记为
合成时间的普通 LRC/SRT/VTT；`force` 对来源逐字时间也重新运行识别。命令行参数为
`--timing-refinement`，旧版 `--no-refine-word-timing` 继续兼容。

## 0.12.0 的可靠锚点与时轴漂移校正

逐词识别时间并不等于音素级强制对齐。为了避免重复副歌、提示词幻觉和局部漏识别把错误
传播到整首歌，当前流程把“文字能匹配”和“时间可作为锚点”分开判断：

1. Whisper 不继承上一解码窗口的文字，减少重复循环和后续时间戳失步；正式歌词只作为
   去重、短小并覆盖全曲的 hotwords 使用。
2. 全局动态规划仍负责按顺序找回正式歌词，但只有相似度足够、置信度合格、时长正常且有
   相邻上下文支持的匹配才能成为时间锚点。
3. 对普通行级 LRC/SRT/VTT，至少三行可靠行首锚点才会形成校正链；算法会寻找覆盖范围较广、
   局部速度比例合理的最长链，再用稳健基线排除跳错副歌的离群点，并在相邻锚点之间插值偏移，
   从而修复整段逐渐变快或变慢的时间轴，而不会让单个或两个误匹配任意拉伸整首歌。
4. 每行重新精修时会同时检查局部覆盖率、平均相似度、精确匹配比例和可信锚点比例；不可靠
   的行保留校正后的原时间，不会把少量识别词强行挤满整句。
5. ASS 导出按每个 token 相对事件起点的绝对厘秒位置生成标签，并插入不可见停顿标签；因此
   首词延迟、拖音后的停顿和每个词的真实起点都能进入最终视频，不再累计舍入误差。

### KTV 精准的逐行 CTranslate2 对齐

KTV 精准不会把整首歌再次作为无边界文本识别。它先保留上述粗对齐文档，再逐行执行：

1. 根据粗对齐行首、行尾和相邻行边界截取一个有限音频窗口；时间重叠或合唱行保留粗对齐，
   不强行套入单声部对齐；
2. 直接编码用户提供的正式歌词 token，把音频特征、起始 token 和正式文本交给
   CTranslate2 Whisper `align`；同一个 `large-v3` 模型实例同时用于粗识别和这一步，
   不重复加载模型；
3. 检查文本覆盖率、token 置信度、时间单调性、行边界和已有来源时间保护条件；通过后
   只替换当前行，未返回有效结果或未通过质量门的行继续使用粗对齐时间；
4. 非重叠行各自独立回填，避免把整首歌词展平成一条全局时间轴后互相推迟。

如果制作伴奏时已经获得人声轨，精准对齐直接复用该轨，不重复执行 Demucs。隐藏歌词不参与
匹配，也不会消耗本应属于可见歌词的演唱锚点。

日语模式可能把同一个英文词拆为多个子词，例如 `d` 与 `reaming`。识别结果根据完整句子文本、
强制对齐根据确切 token 文本核实词界后，才合并同一英文词内部的连续片段；保留原始起止边界，
置信度取片段最低值。空格、标点词界、日文字符以及不同识别片段不会据此合并。

边界检查同时限制大幅裁切的词块比例，以及每个词块的有效声学跨度。完全落在句外的候选不
会被压缩成 10 毫秒后作为可靠结果采纳。小幅边界修正仍允许通过。

旧版 `faster-whisper` 的特征接口可能默认把短句补零到 30 秒；如果把补零后的总帧数传给
对齐器，模型
可能把歌词 token 分散到真实音频之后的静音区，表现为句内忽快忽慢或逐字漂移。0.12.0
提取特征时关闭 30 秒预填充，以短句的真实帧数调用 CTranslate2；只有编码器张量仍按模型
输入尺寸补齐，因此补零不再参与时间换算。

可信的 YRC、增强 LRC 或人工逐字时间默认继续受保护；只有用户选择“强制检查”时才会重新
运行识别，而且不满足严格质量门的修正仍会被拒绝。Whisper 的逐词时间属于基于注意力的
推断结果，复杂和声、强混响和长拖音仍建议在校准工程中试听检查。

### 待复核提示与精度评估

对齐输出会保存逐行复核原因。桌面编辑器持续显示待复核数量，可跳到上一句或下一句；保存、
重开、插入/删除行和撤销时，提示跟随对应歌词。隐藏句的提示暂不计入可见数量，取消隐藏后恢复。
试听确认后，可点击“当前句已核对”清除该句提示；这一步不改时间，支持撤销，重新运行 AI 对齐
后仍可能产生新的复核提示。自动精修失败而退回均分时间时，也会保留提示，不只在日志中报告。

当前提示包括：没有可靠锚点而保留估算时间、部分词仍靠插值、低置信锚点、不超过 20 毫秒的
扫色，以及句内词块重叠。它们是保守的试听提示，不意味着所有被标记的句子都错；没有提示也
不代表已经达到人工校准精度。来源逐字时间没有 ASR 置信度本身不构成错误，拒绝 AI 替换时
继续保留来源时间。

`alignment_review_lines` 保存从 1 开始的工程行号，`alignment_review_reasons` 保存 JSON 原因
映射；`audio_refined_line_indices` 和 `forced_alignment_accepted_line_indices` 记录本次采纳的
行。复核提示不是文本匹配覆盖率：例如 90% 歌词能找到文字对应，仍可能有整句偏移或拖音边界
不准。模型 token 置信度也不能解释成“时间准确率”。

评估日语夹英语的实际精度，需要为有使用权的歌曲建立人工逐字开始/结束标注，在相同音频、
歌词和设备上比较修改前后：边界误差中位数、P90/P95、误差在 100/200 毫秒内的比例，以及重复
副歌错位和漏词数量。快速段、长拖音、间奏前后、英语段和和声应分别统计，不能以“采纳更多行”
代替准确率提升。现有回归测试证明特定算法错误得到修复，真实音频冒烟测试证明推理流程可用；
它们都不能替代上述人工标注评测。

## MV 歌曲起点定位

制作 MV 时可以先对歌曲音频和 MV 内嵌音轨做指纹匹配：

1. FFmpeg 将两条音轨转成低采样率单声道；
2. 每 50 毫秒计算响度和瞬态变化，形成抗 MP3/AAC 压缩差异的能量包络；
3. 从歌曲前、中、后部抽取六个 12 秒窗口，分别在 MV 全轨中搜索；
4. 只有至少三个窗口以相同偏移量匹配、且综合置信度达到阈值时才接受；
5. 接受后同时偏移外部歌曲音轨和歌词时间轴，保留 MV 片头/片尾剧情。

多窗口一致性可以排除重复副歌造成的单点误判。若歌曲版本不同、MV 用了重新编曲版本，
或只能找到孤立窗口，流程会停止并提示素材不匹配，而不是输出错误时间轴。

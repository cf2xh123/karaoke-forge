# 对齐算法

Karaoke Forge 使用“识别定位 + 正式歌词回填”，而不是把语音识别结果直接导出。

1. `faster-whisper` 从歌曲或分离后的人声中生成带开始/结束时间的识别词。
2. 正式歌词和识别词使用相同规则规范化：
   - Unicode NFKC 归一化；
   - 英文等空格语言按单词切分；
   - 中日韩文字按字符切分；
   - 标点保留在显示文本中，但不参与匹配。
3. 全局动态规划按顺序匹配两组词元。完全相同的词权重最高，模糊相似词次之，插入和缺失词使用间隙惩罚。
4. 已匹配词直接采用 ASR 时间；未匹配词在相邻锚点之间插值。
5. 最后按原始歌词行重新组合，生成行级和词级时间轴。

这个方案的主要优点是拼写、标点、大小写和歌词版本由用户控制。其限制也很明确：

- Whisper 的词级时间戳并非音素级强制对齐；
- 歌声、和声、混响和密集伴奏会降低识别质量；
- 大段漏唱或歌词版本不一致会让插值区间变长；
- 中日韩语言目前是字符级高亮，并不自动按语义词或音节合并。

JSON 是信息最完整的中间格式。计划中的高精度后端可以复用同一数据模型，不需要改变其他导出器和视频渲染代码。

## 已有行级时间轴的句内精修

普通 LRC、SRT 和 VTT 往往只标注整句的开始与结束。直接把时间平均分给每个字，会在
拖长音、抢拍和句中变速时造成扫色赶不上或超前。默认精修流程会：

1. 保留输入中每句的开始和结束时间，防止已经对准的行首发生漂移；
2. 用 Whisper 识别整段音频并做一次全局歌词匹配；
3. 取该句匹配到的实际相对节奏，仿射缩放到原来的行区间；
4. 用变速后的逐字/逐词时间替换原先的平均分配结果。

网易云 YRC 已含真实逐字开始时间和持续时间，解析后会标记为来源时间并直接使用，
不再运行这一步。可用 `--no-refine-word-timing` 明确关闭普通行级歌词的音频精修。

## MV 歌曲起点定位

制作 MV 时可以先对歌曲音频和 MV 内嵌音轨做指纹匹配：

1. FFmpeg 将两条音轨转成低采样率单声道；
2. 每 50 毫秒计算响度和瞬态变化，形成抗 MP3/AAC 压缩差异的能量包络；
3. 从歌曲前、中、后部抽取六个 12 秒窗口，分别在 MV 全轨中搜索；
4. 只有至少三个窗口以相同偏移量匹配、且综合置信度达到阈值时才接受；
5. 接受后同时偏移外部歌曲音轨和歌词时间轴，保留 MV 片头/片尾剧情。

多窗口一致性可以排除重复副歌造成的单点误判。若歌曲版本不同、MV 用了重新编曲版本，
或只能找到孤立窗口，流程会停止并提示素材不匹配，而不是输出错误时间轴。
